# Tasks: Noren MVP

**Input**: Design documents from `specs/001-noren-mvp/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md; constitution v1.2.0

**Tests**: Included, but lean (plan decision D13): they protect constitution rules (no ratings, mock flags, sourced sentences, authorisation) and the main flows. Test tasks are marked "Tests" and can be dropped to go faster; the invariants in T028 and T070 are the ones I would keep.

**Organization**: Grouped by user story so each can be built and checked on its own.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: The user story the task serves (US1 to US9)
- **OWNER ACTION**: Needs you (account, dashboard, recording, or a decision). I stop and ask when I reach these.

## Path Conventions

Single Next.js project at the repository root, as in plan.md: `src/`, `convex/`, `regions/`, `scripts/`, `tests/`.

**Convex mapping (2026-10-29, research D19)**: data and server logic live in Convex, not Neon, Drizzle or Blob. Tasks written before the switch name `src/app/api/.../route.ts` handlers and `src/lib/db/...` queries; read each as "the matching Convex query, mutation or action in `convex/`", with the same inputs, role rules and errors as `contracts/http-api.md`. A Next route handler stays only where a plain URL is needed (`/out/:id`, the takedown form post, robots, cron entry points). Role checks run inside the Convex function. Phase 2 tasks below are already rewritten; later tasks are re-pointed when I reach them, and the contract file is the source of truth for behaviour.
